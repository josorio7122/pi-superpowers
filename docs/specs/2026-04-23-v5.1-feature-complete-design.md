# pi-superpowers v5.1 — Feature-Complete Design

**Date:** 2026-04-23
**Status:** Approved for implementation planning
**Supersedes:** `docs/specs/2026-04-23-subagents-v5.1-design.md` (kept as historical context)

## 1. Purpose

Close every known gap in `v5.0.10` so that `pi-superpowers` is genuinely feature-complete:

- Real `superpowers_subagent` integration with `pi-agents.runAgent` — no feature flag.
- Real interactive `/todos` picker via a `pi-tui` `Component` — no feature flag.
- End-to-end coverage for every extension side-effect (widget, status, skills discovery, bootstrap) using marker-file observation.
- Multi-session E2E coverage for edge surfaces (`/tree`, `/fork`, `/resume`, `/new`, `/compact`).

Ships as `v5.1.0`.

## 2. Non-goals

- PTY-based terminal snapshot testing. Interactive rendering is pi's concern; we test our code paths via marker files + unit snapshots. User does final visual QA.
- Subprocess-based subagent dispatch. In-process `pi-agents.runAgent` is the only mode.
- Upstream (`obra/superpowers`) edits. Transform layer absorbs any frontmatter diff.
- Core `pi-agents` changes — open questions from the earlier spec are now resolved without requiring any.

### Key architectural decisions

1. **Delete `src/subagents/dispatch.ts`** — it reimplements pi-agents primitives. Use `executeSingle` / `executeParallel` / `executeChain` from pi-agents directly.
2. **`agent-config-builder`** is the pure function that synthesizes a pi-agents-valid `AgentConfig` from minimal upstream frontmatter. The only place that knows pi-agents' schema requirements.
3. **`run-agent-factory`** curries `pi-agents.runAgent` into the `RunAgentFn` shape expected by the mode helpers. Only place that knows pi-agents' full `RunAgentParams` shape.
4. **`tool.ts` orchestrator** knows only: look up agent by name → build config → build runner → call mode helper → render result. No schema knowledge leaks here.
5. **`TodoPickerComponent`** wraps the existing pure FSM (`src/ui/todo-picker.ts`) behind the pi-tui `Component` interface. FSM stays unit-tested in isolation; component adds only the tui-adapter layer.
6. **No feature flags.** v5.1.0 ships every feature enabled. pi-agents becomes a hard peer dep.

## 5. Components

### 5.1 `AgentConfig` default synthesis table

When the upstream agent file lacks a required pi-agents field, the builder synthesizes these values. Upstream-provided values always win.

| Field | Default | Rationale |
|---|---|---|
| `name` | upstream `name` (required) | — |
| `description` | upstream `description` (required) | — |
| `model` | upstream `model` unless `"inherit"` → `ctx.model.id`; hard error if neither resolves | pi-agents rejects `"inherit"`; we must resolve |
| `role` | `"worker"` | Conservative default; reviewer/scout/etc. are all workers |
| `color` | `"#f5a623"` | Superpowers brand amber |
| `icon` | `"🦸"` | Superpowers brand glyph |
| `domain` | `[{ path: ".", read: true, write: true, delete: false }]` | CC agents assume cwd access; we deny delete as conservative floor |
| `tools` | upstream `tools` (normalized) else `["read", "write", "edit", "bash", "grep", "glob"]` | Matches pi's native tool set; upstream-specified tools pass through |
| `skills` | `[]` | pi discovers skills globally via `pi.skills` manifest — no per-agent binding needed |
| `knowledge.project` | `{ path: "{sessionDir}/superpowers/{agent}-project.md", description: "Project context for <agent>", updatable: true, "max-lines": 500 }` — file created empty if missing | pi-agents requires non-empty zod schema; stub file satisfies shape |
| `knowledge.general` | `{ path: "{sessionDir}/superpowers/{agent}-general.md", description: "General knowledge for <agent>", updatable: true, "max-lines": 500 }` — file created empty if missing | same |
| `conversation.path` | `"{sessionDir}/superpowers/{agent}-{{SESSION_ID}}.jsonl"` | Schema requires `{{SESSION_ID}}` literal; we provide it |
| `reports` | omitted (optional in schema) | No upstream agents currently produce reports |

Knowledge stub files are created lazily by `agent-config-builder` on first dispatch — idempotent, empty markdown files just to satisfy pi-agents' path-exists validation. They are free for the agent to write into if desired.

## 6. Data flow

### 6.1 Subagent dispatch — single

```
model calls superpowers_subagent({ agent: "code-reviewer", task: "review step 2" })
  │
  ├─► tool.execute receives (toolCallId, params, signal, onUpdate, ctx)
  │      ctx provides: modelRegistry, cwd, sessionManager, model, signal
  │
  ├─► loader.findAgent("code-reviewer")          ← vendor/superpowers/agents
  ├─► agent-config-builder.buildAgentConfig(agent, ctx)
  │       validates via pi-agents AgentFrontmatterSchema
  ├─► run-agent-factory.makeRunAgent({ config, cwd, sessionDir, conversationLogPath, modelRegistry, model, signal })
  │       returns RunAgentFn
  ├─► pi-agents.executeSingle({ task, runAgent })
  │       streams to render.ts via onMetrics
  │       returns { output, metrics, error? }
  ├─► render.renderSingleResult({ result, width, theme })
  └─► returns { content: [{text: panel}], details: { mode, agent, metrics, error } }
```

Parallel/chain reuse the same factory; only the mode helper differs.

### 6.2 Interactive /todos command

```
user types /todos
  │
  ├─► command.handler gets (args, ctx)
  ├─► reconstructTodos(ctx.sessionManager.getEntries()) → initial TodoItem[]
  ├─► ctx.ui.custom<TodoItem[]>((tui, theme, keybindings, done) =>
  │       new TodoPickerComponent({ items, theme }, done))
  │
  │     Inside the component:
  │       render(width):  renderPicker({ state, theme, width })
  │       handleInput(k): state = onPickerKey({ state, key: mapKey(k) })
  │                       if state.done: done(state.items)
  │
  ├─► done(finalItems) resolves ctx.ui.custom
  └─► executeTodos(ctx, { action: "replace", items: finalItems })
        writes widget via setWidget marker + updates session state
```

### 6.3 Compaction passthrough

```
user triggers /compact
  │
  ├─► session_before_compact fires
  │      our handler: return undefined (no-op; let pi's default run)
  ├─► pi compacts session history
  ├─► session_compact fires
  └─► our handler:
        todos = reconstructTodos(currentBranchEntries)
        setWidget(ctx, { name: "todos", lines: renderCompactTodo(...) })
        (widget would otherwise be cleared by pi during compaction)
```

## 7. Error handling & degradation

| Failure | Where caught | Response |
|---|---|---|
| `ctx.modelRegistry` missing | `tool.execute` | Tool error result: "pi runtime did not expose modelRegistry" |
| `model: inherit` + `ctx.model` undefined | `agent-config-builder` | Tool error result: "cannot resolve 'inherit' model — no session model set" |
| Upstream frontmatter fails synthesized `AgentFrontmatterSchema` validation | `agent-config-builder` | Throw `AgentConfigBuildError` with specific zod issue; tool surfaces as error result |
| Agent not found by name | `tool.execute` | Tool error result listing available agents |
| `pi-agents.runAgent` throws | `run-agent-factory` wrapper | Captured in `executeSingle/Parallel/Chain` return; rendered as error panel |
| Abort signal triggered mid-dispatch | `pi-agents` handles | Our render shows `⏸ cancelled` + partial text |
| `ctx.ui.custom` unavailable (pi mode with no TUI) | `command.handler` | `ctx.ui.notify` a friendly message, early-return; don't crash |
| Compaction handler errors | `session_compact` handler | Silently ignore — widget absence is not a blocker |

### Explicit non-responses

- **No silent fallbacks.** If a required ctx field is missing, user sees an error result immediately. Hidden degradation masks bugs.
- **No retry loops.** pi owns retry; we surface the first failure cleanly.

## 8. Testing strategy

### Unit (pure logic, ~20 new tests)

- `agent-config-builder.test.ts` — defaults, `model: inherit` translation, schema validation, edge cases (missing tools, malformed fm).
- `run-agent-factory.test.ts` — partial-application wiring, signal passthrough, onMetrics bridge.
- `todo-picker-component.test.ts` — key sequence mapping (`\u001b[A` → `up`, space → `space`, etc.); `render(width)` at widths 40/80/120; done callback triggered on `q`.
- `markers.test.ts` — env-gate behaviour, atomic file write, payload serialization.

### E2E (real pi subprocess; ~8 new + 2 existing)

Fast suite (always runs when `PI_BIN` set):

- `bootstrap/inject-e2e.test.ts` (existing) ✓
- `todos/todos-e2e.test.ts` (existing) ✓
- `subagents/subagents-single-e2e.test.ts` — dispatch `code-reviewer` with a trivial task, assert tool result has `mode: "single"` in details and non-empty output.
- `todos/picker-e2e.test.ts` — marker file confirms `TodoPickerComponent` was constructed when `/todos` fires.
- `ui/widget-e2e.test.ts` — todo add triggers `widget-set` marker with non-empty lines; clear triggers marker with empty lines.
- `ui/status-e2e.test.ts` — session_start triggers `status-set` marker.
- `skills/skill-broadcast-e2e.test.ts` — initial system prompt contains skill-name text (check for at least 5 of the 15).

Slow suite (runs when `E2E_FULL=1`):

- `subagents/subagents-parallel-e2e.test.ts` — two-agent parallel run.
- `subagents/subagents-chain-e2e.test.ts` — two-agent chain, `{previous}` substitution works.
- `multi-session/tree-persistence-e2e.test.ts` — `/tree` branch, todo state reconstructs correctly.
- `multi-session/compact-persistence-e2e.test.ts` — `/compact` preserves widget via our `session_compact` handler.
- `multi-session/new-session-e2e.test.ts` — `/new` re-injects bootstrap.

### Marker-file observation contract

`src/common/markers.ts` is the single funnel. Whenever `SUPERPOWERS_MARKER_DIR` is set:

- `writeMarker("bootstrap-inject", { ts })` — called from `bootstrap/inject.ts`.
- `writeMarker("widget-set", { name, lines })` — called from `ui/widget.ts`.
- `writeMarker("status-set", { text })` — called from `ui/status.ts`.
- `writeMarker("todo-picker-opened", { itemCount })` — called from `TodoPickerComponent` constructor.
- `writeMarker("subagent-dispatched", { mode, agents })` — called from `subagents/tool.ts`.

Tests set `SUPERPOWERS_MARKER_DIR` to a tmpdir, spawn pi, assert expected marker files exist with expected JSON payload.

### Coverage gate

`npm run check` runs lint + typecheck + unit. `npm run test:e2e` runs fast E2E suite. `npm run test:e2e:full` runs slow suite. CI: fast always, full on nightly / release.

## 9. Release

- Version bump: `5.0.10` → `5.1.0` (minor bump: substantial features, no breaking API; existing feature-flag env vars become no-ops).
- **User-facing install change:** `pi-agents` was a soft peer before (only needed if subagent flag was on); in v5.1 it is a **required peer**. Install docs:
  ```
  pi install git:github.com/josorio7122/pi-agents
  pi install git:github.com/josorio7122/pi-superpowers@v5.1.0
  ```
  If users omit pi-agents, pi will fail to load pi-superpowers with a clear error from the extension loader.
- `README.md` updated — remove feature-flag table; add troubleshooting section covering: missing pi-agents, `model: inherit` resolution failures, agent-not-found errors.
- Release notes: clear inventory of what's new + migration note for anyone who set the old env flags (flags are ignored in v5.1).

## 10. Open questions

- **Compaction re-inject**: we don't know for certain that pi's `/compact` clears widgets vs preserves them. Plan assumes "clears"; if it preserves, our `session_compact` handler becomes a no-op. Behaviour verified in `compact-persistence-e2e.test.ts`; if wrong, one-line fix.
