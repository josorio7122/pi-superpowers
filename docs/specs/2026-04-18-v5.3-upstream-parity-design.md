# v5.3 Upstream Parity + Programmatic Sync

**Date:** 2026-04-18
**Status:** Design
**Target release:** v5.3.0

## Goal

Reposition pi-superpowers as a **faithful adapter** of `obra/superpowers`: every skill, command, and agent upstream ships is picked up automatically on sync; nothing beyond what upstream needs lives in the registration layer; drift is caught by CI.

"Parity" is defined by upstream's three registration surfaces:

1. `vendor/superpowers/skills/*/SKILL.md`
2. `vendor/superpowers/agents/*.md`
3. `vendor/superpowers/commands/*.md`

Extensions that fill pi platform gaps (no built-in `Skill`, `Task`, `TodoWrite`) are in scope because upstream skills explicitly require them. Extensions that add UX beyond what upstream uses are out of scope.

## Architecture

Four generic loaders walk the vendored tree and register everything they find. The only hand-maintained list is the built-in `general-purpose` agent (not vendored because upstream delegates it to Claude Code's runtime). A parity-check script enumerates vendor content and asserts 1:1 with runtime registrations — so any new upstream surface (new skill, new command, or a new category like `mcp-servers/`) fails the build until it has a handler.

## New Code

### `src/commands/loader.ts`

Scans `vendor/superpowers/commands/*.md`, parses frontmatter, returns an array of command descriptors. Registration happens in `index.ts`.

```ts
import { readFile } from "node:fs/promises";
import { basename } from "node:path";
import { glob } from "glob";
import { parseFrontmatter } from "../subagents/frontmatter.js";

export type CommandDescriptor = {
  name: string;
  description: string;
  body: string;
};

export async function loadCommands(vendorRoot: string): Promise<CommandDescriptor[]> {
  const files = await glob("commands/*.md", { cwd: vendorRoot, absolute: true });
  const descriptors = await Promise.all(
    files.map(async (file) => {
      const raw = await readFile(file, "utf-8");
      const parsed = parseFrontmatter(raw);
      const name = basename(file, ".md");
      const description = typeof parsed.data.description === "string" ? parsed.data.description : name;
      return { name, description, body: parsed.body.trim() };
    }),
  );
  descriptors.sort((a, b) => a.name.localeCompare(b.name));
  return descriptors;
}
```

### `src/commands/handler.ts`

```ts
import type { CommandDescriptor } from "./loader.js";

export type CommandHandler = (args: string, ctx: unknown) => Promise<void>;

export function buildCommandHandler(cmd: CommandDescriptor): CommandHandler {
  return async (_args, ctx) => {
    const anyCtx = ctx as { ui: { setEditorText: (text: string) => void; notify: (msg: string, level: string) => void } };
    if (!cmd.body) {
      anyCtx.ui.notify(`/${cmd.name}: no body — upstream command has only frontmatter`, "info");
      return;
    }
    anyCtx.ui.setEditorText(cmd.body);
  };
}
```

Deprecated upstream commands (`/brainstorm`, `/write-plan`, `/execute-plan`) ship as-is — their body tells the user to use the skill instead, preserving upstream's deprecation UX.

### Wiring in `src/index.ts`

```ts
const commands = await loadCommands(vendorRoot());
for (const cmd of commands) {
  pi.registerCommand(cmd.name, {
    description: cmd.description,
    handler: buildCommandHandler(cmd),
  });
}
```

### `src/parity/check.ts`

Drift detector invoked by CI. Returns a report, throws on mismatch.

```ts
export type ParityReport = {
  missing: { skills: string[]; agents: string[]; commands: string[] };
  extras: { skills: string[]; agents: string[]; commands: string[] };
  unknownCategories: string[];
};

export async function runParityCheck(vendorRoot: string): Promise<ParityReport> {
  // 1. Enumerate vendor/superpowers/{skills,agents,commands}/
  // 2. Call loadSkills(), loadAgents(), loadCommands()
  // 3. Diff each category; flag missing + extras (extras allowed only for built-in agents list)
  // 4. Scan vendor/superpowers/*/ for any subdirectory not in {skills, agents, commands, hooks, docs, scripts, tests}
  //    and report as unknownCategories
}
```

Built-in `general-purpose` agent is whitelisted as a known extra (it's not vendored, it's pi-native).

### `scripts/parity-check.ts`

CLI wrapper:

```ts
#!/usr/bin/env tsx
import { resolve } from "node:path";
import { runParityCheck } from "../src/parity/check.js";

const report = await runParityCheck(resolve(process.cwd(), "vendor/superpowers"));
const hasDrift =
  report.missing.skills.length > 0 ||
  report.missing.agents.length > 0 ||
  report.missing.commands.length > 0 ||
  report.extras.skills.length > 0 ||
  report.extras.agents.length > 0 ||
  report.extras.commands.length > 0 ||
  report.unknownCategories.length > 0;

if (hasDrift) {
  console.error("Parity drift detected:");
  console.error(JSON.stringify(report, null, 2));
  process.exit(1);
}
console.log("Parity OK");
```

Added to `package.json`:

```json
{
  "scripts": {
    "parity-check": "tsx scripts/parity-check.ts",
    "check": "biome check . && tsc --noEmit && vitest run && npm run parity-check"
  }
}
```

## Sync Guarantee

After v5.3.0, `./scripts/sync-upstream.sh vX.Y.Z` + `npm run check` is the complete update cycle. Outcomes:

| Upstream change | What happens |
|---|---|
| New skill directory | Loaded automatically by `resources_discover`; parity-check passes |
| New agent file | Loaded by `loadAgents()`; dispatchable via `superpowers_subagent`; parity-check passes |
| New command file | Registered by commands loader; parity-check passes |
| New top-level category (e.g. `mcp-servers/`) | Parity-check fails with `unknownCategories: ["mcp-servers"]` → we add a loader |
| Removed skill/agent/command | Parity-check shows `extras` if we still reference it; prompts cleanup |

## Testing Approach

- **Unit tests:** loader parsing (frontmatter edge cases, missing description, empty body), handler behavior (setEditorText called with body, notify on empty body), parity-check report shape
- **Integration test:** `src/parity/check.test.ts` runs the full check against real `vendor/superpowers/` and asserts zero drift — so `npm run check` is the gate
- **E2E test:** register a real pi extension, trigger an upstream command, verify `setEditorText` was called with the command body

## Breaking Changes

- `superpowers_subagent` schema no longer accepts `{ chain: [...] }` — users on `single` or `parallel` unaffected
- `/todos` slash command removed — users manage todos via the agent calling `superpowers_todo`

## Error Handling

- `loadCommands` treats a missing `commands/` directory as empty (upstream may drop the category) — returns `[]`
- Malformed frontmatter throws with a clear message identifying the file — fails fast during extension load
- `parity-check` exits 1 on any drift; CI blocks merge

## Out of Scope

- Tool-result injection primitive (`coctostan-plus` style warnings) — separate future design
- `workflow_reference` on-demand tool — separate future design
- Contributing a `references/pi-tools.md` upstream to obra/superpowers — separate effort
- File-based state persistence (`.pi/superpowers-state.json`) — separate future design
